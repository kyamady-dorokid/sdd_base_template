# 日本語の書き方ルール（平易な日本語）

kiro-*スキルが生成する人間向けの日本語プローズ（requirements.md/design.md/tasks.mdの説明文、
Introduction、Objective節、steeringドキュメント、検証レポートなど）に適用する、唯一の正
（SSOT）ルール。各スキルのSKILL.mdやrules/配下のファイルには、このドキュメントへの参照だけを
置き、ルール本文を重複させない。

## 適用範囲

**このルールはEARSのトリガー英語（`When` / `If` / `While` / `Where` / `The [system] shall`）
には適用しない。** トリガー英語はそのまま残す（テスト可能性・システム間整合のため）。このルールが
対象とするのは、日本語で書かれる可変部分・説明文プローズだけである。トリガー英語の扱いは
`kiro-spec-requirements/rules/ears-format.md` を参照。

## ルール1: 一文一義にする

一文で1つの主張だけを述べる。「、」で2つ以上の主張をつなげない。長い一文は「。」で分けて
短くする。

## ルール2: かたい漢語よりやさしい言い回しにする

読み手が意味を即座につかめる言い回しを選ぶ。以下は参考例であり、網羅リストではない。文脈に
応じて同じ考え方で言い換える。

| かたい表現 | やさしい言い換え |
|---|---|
| 識別可能な | 〜とわかる |
| 既定値 | デフォルト／何も指定しなければ |
| 疎通（確認） | 接続確認 |
| 担保する | 守る |
| 冪等性 | 何度実行しても同じ結果になること |

## ルール3: 具体例は「」で示す

エラーメッセージやコマンド出力など、実際に表示・出力される文字列は「」で囲んで示す。読み手が
何が出るのかをその場でイメージできるようにする。

## ルール4: requirements.mdのObjective節は自然な日本語にする

EARSのObjective節（英語型の `As a X, I want Y, so that Z`）を直訳した硬い文にしない。代わりに、
「〜したい。〜するためである。」のような短い2文で、自然な日本語の説明文として書く。

例:
- Before（直訳調）: 「As an operator, I want システムがXを行うこと, so that Yを実現できる」
- After（自然な日本語2文）: 「（誰が）Xしたい。Yを実現するためである。」
